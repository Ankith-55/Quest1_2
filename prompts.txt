We are building a system to locate the first occurrence of a spoken target phrase in a video and extract the timestamp. This is the **core ML model** step, before adding backend API and frontend. ## Task
Create all required files inside `backend/ml/` that implement the following pipeline:

1. **Download audio only** from a given video URL using `yt-dlp` (bestaudio format) and convert to 16kHz mono WAV using `ffmpeg`.
2. **Transcribe** the audio using OpenAI Whisper **`large`** model with `word_timestamps=True`. Save the full transcript as JSON for debugging.
3. **Fuzzy match** the target phrase in the transcript using a sliding window over word-level timestamps. Use `rapidfuzz` with both `ratio` and `partial_ratio`. Threshold default `0.9`. Return the best match (start timestamp, matched text, confidence score) or a list of best candidates if none above threshold.
4. Provide a command-line script that takes a video URL and target phrase as arguments, runs the pipeline, prints results, and saves debug files (`transcript.json`, `result.json`) into an output directory.

## Files to Create (all inside `backend/ml/`)

### `downloader.py`
- Function `download_audio(url: str, output_dir: str = "audio") -> Path`
  - Use `yt-dlp` with `format="bestaudio/best"` to download audio.
  - Convert to WAV using `ffmpeg`: `ffmpeg -y -i input -vn -acodec pcm_s16le -ar 16000 -ac 1 output.wav`
  - Return path to WAV file.
  - Ensure output directory exists.
- Include error handling and logging.

### `transcriber.py`
- Function `transcribe(audio_path: Path, model_size: str = "large", output_json: Path = None) -> dict`
  - Load Whisper model with specified size.
  - Call `model.transcribe(str(audio_path), word_timestamps=True)`
  - If `output_json` provided, save the result dict as JSON.
  - Return the result dict (contains `segments` with `words`, `start`, `end`, `text`).

### `matcher.py`
- Function `normalize(text: str) -> str`
  - Lowercase, remove punctuation, collapse multiple spaces.
- Function `find_phrase(transcript: dict, target: str, threshold: float = 0.9) -> dict`
  - Normalize target and split into words.
  - Extract all words from transcript segments (`segment["words"]`) with their `start`, `end`, `word`, and `score`.
  - Use a sliding window of N consecutive words where N = word count of target (after normalization).
  - For each window, join words, normalize, and compute `rapidfuzz.fuzz.ratio` and `fuzz.partial_ratio`.
  - If score >= threshold, add to candidates.
  - Return:
    - If found: `{"status": "found", "start": float, "text": str, "score": float, "candidates": [...]}`
    - If not found: `{"status": "not_found", "candidates": [...]}` where candidates are the top 10 by score, sorted descending.
  - Ensure timestamps are floats (seconds).

### `locate_phrase.py` (main script)
- Accept command-line arguments: `python locate_phrase.py <video_url> <target_phrase>`
- Create an output directory (`output/` by default) to store artifacts.
- Step 1: Download audio using `downloader.download_audio(url, output_dir/"audio")`
- Step 2: Transcribe using `transcriber.transcribe(audio_path, "large", output_dir/"transcript.json")`
- Step 3: Find phrase using `matcher.find_phrase(transcript, target, threshold=0.9)`
- Print:
  - If found: `Found: '<text>' at <start>s (score <score>)` and save `result.json` with `{"timestamp": start, "text": text, "confidence": score}`.
  - If not found: print `Phrase not found above threshold. Best candidates:` and list top 5 with score, start, text.
- Include basic logging with step numbers.

The pipeline currently accepts a video URL and target phrase, downloads/uses cached media, transcribes with Whisper, locates phrase occurrences, extracts frames, and saves results into a new timestamped folder inside `backend/ml/results/`.

Requirements:

1. **Project Structure**:
   - Create a new package `backend/app/` (alongside `backend/ml/`) containing:
     - `main.py` – FastAPI app initialization, static file serving.
     - `api/routes.py` – Endpoints.
     - `api/schemas.py` – Pydantic models.
     - `core/config.py` – Settings from environment.
     - `services/pipeline.py` – Wraps the ML pipeline call (import from `backend.ml`).
     - `services/job_manager.py` – In-memory job store with thread lock.
   - The existing `ml/` folder should be importable; add `__init__.py` files as needed.

2. **API Endpoints**:
   - `POST /jobs`:
     - Accepts JSON body: `{"url": str, "target_text": str, "model_size": str = "base", "threshold": float = 0.9}`.
     - Creates a job, returns `{"job_id": str, "status": "queued"}` with HTTP 202.
     - Starts the pipeline in a background thread using FastAPI `BackgroundTasks`.
   - `GET /jobs/{job_id}`:
     - Returns current job status: `queued`, `processing`, `completed`, `failed`.
     - If completed, includes `result` object with:
       - `timestamp` (formatted HH:MM:SS.sss)
       - `frame_number` (integer)
       - `text` (matched phrase text)
       - `confidence` (score)
       - `image_path` (relative path to saved frame inside the job's output folder)
       - `matches` (list of all matches above threshold, each with timestamp, frame_number, text, image_path)
     - If failed, includes `error` string.
     - Returns 404 if job not found.

3. **Integration with ML Pipeline**:
   - Import functions from `backend.ml` (e.g., `locate_phrase` run function, or the individual download/transcribe/match/extract functions).
   - You may need to refactor `locate_phrase.py` to expose a callable function `run_pipeline(url, target_text, model_size="base", threshold=0.9, output_base_dir=Path("results"))` that returns a dict with the result summary. This function should handle caching, create a new run folder, save output files, and return paths.
   - Ensure the background task calls this function and updates the job status accordingly.

4. **Static File Serving**:
   - Serve the `backend/ml/results/` directory (or a dedicated output directory) at `/output` using FastAPI `StaticFiles`.
   - The returned `image_path` should be a relative path like `20260825_175305/frames/frame_1_00_01_33_200.png` that can be appended to `/output/` to access the image.

5. **Configuration**:
   - Use environment variables for `MODEL_SIZE` (default `base`), `FUZZY_THRESHOLD` (default `0.9`), `OUTPUT_BASE_DIR` (default `backend/ml/results`), `MAX_CONCURRENT_JOBS` (optional).
   - Provide a `.env.example`.

6. **Error Handling**:
   - Catch exceptions in the pipeline, update job to `failed` with error message.
   - Validate input: URL must be non-empty, target text must be non-empty.
   - Log all steps.

7. **Testing**:
   - Add basic unit tests for `job_manager.py` and API routes (using FastAPI TestClient). Mock the pipeline call to avoid long runs.
   - Ensure CI can run tests without downloading large models.

8. **Documentation**:
   - Add comments explaining the flow.
   - Update README with how to run the backend (uvicorn command).
   - Include `requirements.txt` additions if needed (fastapi, uvicorn, pydantic, python-multipart? not needed for JSON).
